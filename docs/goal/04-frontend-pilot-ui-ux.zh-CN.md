## 目标结果

把当前可运行但偏调试用途的前端，改造成可用于试点实验的中文实验界面。本目标现在只关注 **UI/UX**：信息架构、被试流程、研究者仪表盘交互、问卷呈现、对话呈现、文案、错误/加载状态，以及前端测试。

除“前端必须正确渲染后端返回的问卷定义”之外，问卷题目文字、题目数量、题项映射、计分规则和问卷版本都不属于本目标范围。

## 范围边界

### 本目标包含

- 区分被试端和研究者管理端。
- 被试端分阶段流程。
- 主要阶段前的中文指导语。
- 问卷 UI 控件、分组、进度、校验、提交锁定反馈。
- AI 对话 UI 和完成进度展示。markdown渲染。
- 研究者仪表盘布局与操作确认。
- 敏感导出警告。
- 面向用户的加载、错误、成功状态。
- 覆盖关键被试路径和管理端路径的前端测试。

### 本目标不包含

- 修改问卷题目文字。
- 修改问卷题目数量。
- 修改 U-MICS 维度或计分。
- 重新引入 DIDS。
- 修改问卷版本。
- 后端逐题自动保存。
- 最终高保真视觉设计或深度视觉打磨。

## 已确认的产品 / UX 决策

1. **被试界面隐藏分组和管理端内部信息。** 被试不能看到实验组/控制组标签、分组来源、实验会话 ID、prompt mode、后端状态字段、provider 元数据、导出控件、重置/排除控件或任何研究者管理端内部信息。
2. **被试流程由系统控制并且单向推进。** 被试可以刷新并恢复当前阶段，但不能手动跳过阶段、提前进入后测，或重复提交已锁定的问卷。
3. **问卷 UI 需要分组且易读。** 不要展示一条很长的原始题目列表。使用中性的中文分组标题和进度提示。不要向被试暴露英文量表名称。
4. **问卷填写不要求后端逐题自动保存。** 在同一前端会话内保留已填写答案；刷新或离开前提示未保存答案；提交前校验缺失作答；提交失败后保留答案；提交成功后显示已提交并锁定状态。
5. **研究者仪表盘默认不显示完整原始聊天。** 原始聊天仅通过带有明确确认的敏感导出包提供，不在仪表盘内联浏览。
6. **AI 对话必须 promptless。** 后端不得向模型发送系统提示词、developer instruction、base instruction 或任何模型侧话题引导；但被试界面可以展示“围绕专业/未来方向”等可见任务说明，因为这是研究话题本身，不属于隐藏系统提示词。
7. **回复速度验收为 10 秒。** 优先使用 Codex GPT-5.5；如果 Codex 不能在 10 秒内给出可用回复，应降级到 DeepSeek/OpenAI-compatible provider。
8. **移动端 chat 是手机优先的单屏体验。** chat 页面在移动端和电脑端都不得横向滚动或左右拖动；长文本必须在视口内换行，输入框必须始终可触达。
9. **视觉基调可信、安静、低干扰。** UI 应该像研究实验平台，而不是治疗、咨询或强陪伴感 AI 产品。

## UI/UX 需求

### 1. 顶层角色区分

第一个页面应该展示两个清晰角色，而不是一次性暴露所有操作：

```text
Mentor Echo AI 对话实验平台

[我是被试，进入实验]
[我是研究者，进入管理后台]
```

被试界面不得显示管理端操作、分组内部信息、分组标签、分组来源、session ID、prompt mode、后端状态字段、导出控件、重置/排除按钮或 provider 元数据。

研究者界面必须先登录，登录后才能显示导入、仪表盘、重置、排除、导出、审计/行为摘要或敏感数据操作。

### 2. 被试流程

被试 UI 应该是由后端 session 状态控制的中文分阶段流程：

1. 被试编号进入；
2. 实验说明 / 欢迎指导语；
3. 前测问卷；
4. AI 对话说明；
5. AI 对话；
6. 后测问卷；
7. 完成页。

使用“AI 对话”等中性表达。除非研究者后续明确要求，否则不要告诉被试其处于实验组还是控制组。

### 3. 阶段指导语

初始实验说明：

```text
欢迎参加本实验

本实验包含：
1. 前测问卷
2. AI 对话
3. 后测问卷

你需要使用研究者提供的被试编号进入。
平台不会收集你的姓名。

[我已了解，开始]
```

AI 对话前说明：

```text
AI 对话说明

请根据页面中的 AI 回应进行自然对话。
有效完成对话需要同时满足：

- 至少发送 10 条消息
- 对话时间至少 15 分钟

达到条件后，系统会开放“结束对话并进入后测”按钮。

[开始 AI 对话]
```

后测前说明：

```text
你已完成 AI 对话，下面将进入后测问卷。
请根据刚才的对话体验作答。
```

### 4. 问卷呈现

渲染后端返回的问卷定义。不要在前端硬编码或重新解释问卷内容。

数值量表题应使用可点击的量表控件，不使用下拉框。

5 点量表示例：

```text
完全没有    ○   ○   ○   ○   ○    非常严重
            1   2   3   4   5
```

7 点量表示例：

```text
非常不同意  ○ ○ ○ ○ ○ ○ ○  非常同意
             1 2 3 4 5 6 7
```

语义差异题示例：

```text
这个 AI 更像一个工具     ○ ○ ○ ○ ○     这个 AI 更像是在和我交流
```

分类题应使用可见的选项按钮或卡片，不使用下拉框：

```text
您的性别

[男] [女]
```

```text
您目前在读：

[大一] [大二] [大三] [大四] [硕士研究生] [博士研究生]
```

### 5. 问卷分组 / 分页

根据题项元数据、量表和主题使用中性的中文分组。建议分组如下。

前测：

1. 基本信息；
2. 身份困扰；
3. 专业选择相关题项；
4. 检查并提交。

后测：

1. 身份困扰；
2. AI 感知能力；
3. AI 拟人感；
4. 对话体验；
5. 专业选择相关题项；
6. 检查并提交。

展示进度：

```text
前测问卷  第 2 / 4 部分
进度：██████░░░░ 40%

[上一页] [下一页]
```

提交页应提示：

```text
请确认所有题目已完成。提交后将锁定，不能自行修改。
[提交前测]
```

### 6. 对话 UI

把当前偏调试风格的消息列表替换成手机优先、单屏可用的聊天界面，并清楚展示完成进度。被试界面可以保留“围绕专业与未来方向”等可见任务说明；promptless 规则只限制后端传给模型的隐藏提示词 / instruction，不限制被试看得见的研究任务文案。页面在移动端和电脑端都必须禁止横向滚动：不能左右拖动，消息气泡不能撑出视口，长文本必须自动换行，输入框在移动端单屏体验中始终可触达。

可见进度文案：

```text
完成要求：
消息数：3 / 10
对话时长：04:21 / 15:00
当前状态：尚未达到完成条件
```

未满足完成条件时：

```text
[尚未达到完成条件，暂不能进入后测]
```

满足完成条件后：

```text
消息数：10 / 10
对话时长：15:02 / 15:00
当前状态：已达到完成条件

[结束对话并进入后测]
```

文案必须清楚说明：完成资格由平台规则判断，不是由 AI 批准。加载文案只展示“正在生成回复”等被试友好的状态；不得向被试暴露 provider 名称、thread id、prompt 细节、timeout 内部信息或降级机制。

### 7. 研究者仪表盘 UI

研究者仪表盘应包含汇总卡片：

- 总被试数；
- 未开始；
- 前测完成；
- 对话中；
- 已完成；
- 已排除。

操作表格：

```text
被试编号 | 分组 | 来源 | 状态 | 前测 | 对话轮次 | 对话时长 | 后测 | 排除 | 最后访问 | 操作
```

重置、排除和导出应使用确认弹窗：

- 重置需要填写原因；
- 排除需要填写原因；
- 导出需要提示 ZIP 包含敏感原始聊天 `chat_messages.jsonl`。

仪表盘默认不得显示完整原始聊天。

## 验收标准

- [ ] 被试流程和研究者流程在视觉和功能上分离。
- [ ] 被试界面隐藏分组标签、分组来源、session ID、prompt mode、后端状态字段、provider 元数据、导出/重置/排除控件和管理端内部信息。
- [ ] 被试流程由系统控制：进入 → 指导语 → 前测 → AI 指导语 → 对话 → 后测 → 完成。
- [ ] 问卷 UI 使用可点击量表控件、分类按钮/卡片、分组/分页、进度、必答校验和提交锁定反馈。
- [ ] 问卷 UI 正确渲染 `mentor_echo_questionnaire_v2026_05_15_major_umics_only` 的后端内容，不修改题目文字或计分假设。
- [ ] AI 对话 UI 展示 10 条消息 + 15 分钟的完成进度，并用中文解释未达标/已达标状态。
- [ ] 对话 provider 调用必须 promptless：无系统提示词、developer instruction、base instruction 或模型侧话题引导。
- [ ] 优先使用 Codex GPT-5.5，但必须在 10 秒内通过 Codex 或降级 provider 给被试可用回复。
- [ ] 移动端 chat 在 375×667 和 390×844 下是手机优先单屏体验：无横向滚动、无左右拖动、消息文本自动换行、输入框可触达。
- [ ] 电脑端 chat 同样不得出现页面或 chat 区域横向溢出。
- [ ] 研究者仪表盘支持试点操作：汇总卡片、表格、重置/排除确认、导出确认、敏感原始聊天警告。
- [ ] 仪表盘默认不内联展示完整原始聊天。
- [ ] 加载、错误、成功、阻塞、锁定等状态使用可理解的中文文案。
- [ ] 前端测试覆盖关键被试路径和研究者 UI 路径。
- [ ] 现有后端回归测试仍然通过。
